# PR Summary: Auto Partition Lifecycle Scaling

## Summary

This PR automates the room partition lifecycle for hot rooms:

- detects stable hot-room scale-up candidates from cluster workload summary
- scales room partition count up
- reconnects existing clients for redistribution
- detects sustained low workload
- safely drains high partition ids
- completes scale-down only after cluster-wide draining sessions reach zero

Production defaults remain disabled. The lifecycle loop only runs when explicitly enabled.

## Main Changes

### Lifecycle control loop

- Added `RoomPartitionLifecycleProperties`.
- Added `RoomPartitionLifecycleScheduler`.
- Scheduler runs only with `app.room-partition.lifecycle.enabled=true`.
- Scheduler acquires a Redis lease before acting:

```text
openchat:room-partition:lifecycle:lease
```

- Room action cooldowns use Redis keys:

```text
openchat:room-partition:lifecycle:cooldown:{operation}:{roomId}
```

### Scale-up

- Added `RoomPartitionLifecycleService`.
- Uses `SCALE_UP_CANDIDATE` recommendations from cluster summary.
- Skips automatic scale-up when stale-node or send-failure recommendations are present.
- Requires repeated stable observations before acting.
- Requires existing state to be `ACTIVE`.
- Computes target as:

```text
candidateTarget = max(candidate.effectivePartitions, currentPartitions + 1, 2)
target = min(candidateTarget, maxPartitionsPerRoom, configuredPartitionCount)
```

- Calls:

```text
scaleUp -> redistribute -> completeScaleUp
```

### Redistribution

- Added `RoomPartitionRedistributionService`.
- Sends reconnect controls to old partition ranges after scale-up.
- Uses reason:

```text
partition_rebalance
```

- Reconnect publish failure does not roll back scale-up.

### Scale-down / drain

- Added `RoomPartitionScaleDownService`.
- Default behavior only scales down auto-managed rooms.
- Scale-down starts drain instead of immediately reducing `partitionCount`.
- Drains high partition ids first:

```text
4 -> 2 drains 2,3
2 -> 1 drains 1
```

- Completion requires cluster-wide draining sessions to be zero for consecutive observations.
- Until completion, reconnect controls are sent to draining partitions with cooldown.

### Snapshot and summary

- Added `RoomPartitionDrainProgress`.
- Extended `RealtimeNodeWorkloadSnapshot` with `drainProgress`.
- Extended `RealtimeWorkloadClusterSummary` with aggregated `drainProgress`.
- Missing JSON field is treated as an empty list for backward compatibility.

### k6 smoke support

- k6 now handles `room.reconnect` control frames.
- On reconnect control:
  - stops new sends
  - waits briefly for pending acks
  - flushes counters
  - closes socket
  - calls `/ws-route`
  - reconnects to the routed partition
- Added metrics:

```text
ws_reconnect_controls_received_total
ws_route_partition_count
ws_route_partition_id
```

### GCP load test

- Added lifecycle smoke profile:

```text
infra/gcp-loadtest/profiles/room-partition-auto-lifecycle-smoke.tfvars.example
```

- Added room partition state dumps and lifecycle env wiring to GCP startup templates.

## Risk Notes

- Lifecycle is disabled by default in production config.
- Auto scale-down defaults to auto-managed states only.
- Reconnect publish failures are observable through logs/metrics and do not roll back scale-up.
- Final smoke validates one full scale-up and one safe scale-down. The code can continue later with additional `2 -> 1` drain if cooldown allows.

## Follow-Up

Dynamic realtime partition ownership is the next design topic. Current GCP smoke still uses explicit partition ownership through environment configuration.
