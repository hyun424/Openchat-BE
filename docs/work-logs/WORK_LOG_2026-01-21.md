
# 작업 로그 - 2026-01-21

## 문제 상황

1. **실시간 메시지 전달 실패**: 한 창에서 보낸 메시지가 다른 창에서 보이지 않음
2. **새로고침 후 메시지 순서 깨짐**: DB에서 불러온 메시지 순서가 맞지 않음
3. **멀티 서버 환경 문제**: 8080, 8081 두 서버 운영 시 일부 클라이언트만 메시지 수신

---

## 근본 원인 분석

### 1. Redis Dedupe의 잘못된 설계
```
기존 흐름:
Server A: Redis dedupe key 설정 → FANOUT ✅
Server B: Redis dedupe key 존재 → DEDUPED ❌ (자신의 세션에 전달 안 함)
```

- Redis dedupe가 **전체 클러스터 기준**으로 동작
- 먼저 처리한 서버만 fan-out, 나머지 서버는 skip
- 결과: 일부 클라이언트만 메시지 수신

### 2. Kafka Consumer 간섭
- `ChatKafkaConsumer`에 `@ConditionalOn` 어노테이션 없음
- Kafka가 실행 중이면 Redis Subscriber와 동시에 `fanout()` 호출
- Kafka가 먼저 dedupe 키 설정 → Redis Subscriber는 항상 DEDUPED

### 3. 메시지 순서 불일치
- `createdAt`만으로 정렬 시 동일 밀리초 내 순서 불확정
- `timestamp`가 String 타입으로 저장되어 정렬 오류 가능성

## 해결 방안

### 1. 인메모리 Per-Instance Dedupe로 전환

**Before (Redis 기반):**
```java
// 전체 클러스터에서 1회만 처리
String dedupeKey = "dedupe:chat:" + messageId;
Boolean first = redisTemplate.opsForValue().setIfAbsent(dedupeKey, "1", Duration.ofMinutes(1));
```

**After (인메모리 기반):**
```java
// 각 인스턴스에서 1회씩 처리
ConcurrentHashMap<String, Long> dedupeCache = new ConcurrentHashMap<>();
Long previous = dedupeCache.putIfAbsent(messageId, System.currentTimeMillis());
```

**장점:**
- Redis 의존성 제거 (latency 감소)
- 서버 간 간섭 없음
- 각 서버가 자신의 로컬 세션에 독립적으로 fan-out

### 2. Kafka Consumer 조건부 활성화

```java
@ConditionalOnProperty(name = "chat.fanout.mode", havingValue = "kafka")
public class ChatKafkaConsumer { ... }
```

- 기본: Redis Pub/Sub가 실시간 fan-out 담당
- `chat.fanout.mode=kafka` 설정 시에만 Kafka Consumer 활성화
- Kafka는 내구성/순서 보장용 저장소로만 사용

### 3. 메시지 순서 보장

**DTO 수정:**
```java
// Before
private String timestamp;

// After
private Long createdAt;  // epoch millis
```

**Repository 수정:**
```java
// Before
findByRoomIdAndCreatedAtGreaterThanOrderByCreatedAtAsc(...)

// After - 복합 정렬
findByRoomIdAndCreatedAtGreaterThanEqualOrderByCreatedAtAscIdAsc(...)
```

### 4. Publisher 자동 감지

| 조건 | 활성화되는 Publisher |
|------|---------------------|
| Kafka 설정 있음 | `ChatCompositePublisher` (Redis + Kafka) |
| Redis만 설정 | `ChatRedisOnlyPublisher` |
| 둘 다 없음 | `NoopChatMessagePublisher` |

## 최종 아키텍처

```
WebSocket Client
       │
       ▼
ChatWebSocketHandler (I/O only)
       │
       ▼
ChatIngestService
       │
       ├─1─▶ DB Save (MySQL) ─────────────▶ 정합성 원천
       │
       └─2─▶ Redis PUBLISH
                  │
       ┌─────────┴─────────┐
       ▼                   ▼
  Server 8080          Server 8081
  (Redis Sub)          (Redis Sub)
       │                   │
       ▼                   ▼
  fanout()             fanout()
  (in-memory           (in-memory
   dedupe)              dedupe)
       │                   │
       ▼                   ▼
  Local WS             Local WS
  Sessions ✅          Sessions ✅
```

## 테스트 방법

```bash
# 터미널 1
./gradlew bootRun --args='--server.port=8080 --app.instance-id=8080'

# 터미널 2
./gradlew bootRun --args='--server.port=8081 --app.instance-id=8081'
```

**확인 사항:**
1. ✅ User1 메시지 → User2 실시간 수신
2. ✅ User2 새로고침 → 메시지 순서 정상
3. ✅ 양쪽 서버의 클라이언트 모두 메시지 수신
